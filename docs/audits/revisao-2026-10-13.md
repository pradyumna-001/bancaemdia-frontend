## Bloqueio comprovado: escolha de tipster na consolidação

- `ResolucaoNova` permite somente `acao` e `aposta_corrigida`, com `extra="forbid"`. A ação MESMA chama `confirmar_par` sem escolha de tipster.
- `consolidate` recusa dois tipsters diferentes quando `tipster_choice` é ausente. Esta pendência é válida e criada pelo próprio servidor como `consolidacao_pendente`.
- POST `/api/v1/consolidacoes` aceita `tipster_choice`, mas exige os IDs numéricos persistidos das duas apostas. `RevisaoSaida` publica chaves em `extracao_bruta`; `BetResponse`/`BetDetailResponse` não publicam esses IDs. O site não consegue formar o pedido alternativo a partir da leitura disponível.
- Corrigir o tipster de uma fonte para simular a escolha, converter chave em ID ou descartar uma aposta para eliminar o conflito alteraria fatos/semânticas. Não são alternativas aceitáveis.

## Contratos que precisam de alinhamento no mesmo PR

- A leitura de revisão mantém família, referências de aposta/par, dados extraídos e contexto de conta em JSON aberto. Publicar a projeção segura e as ações permitidas por motivo evita que o frontend deduza elegibilidade, lado financeiro/contextual ou vigência de conta. Reutilizar os contratos existentes, sem refazer o domínio.
- Os filtros `desde`/`ate` da revisão consultam `RevisaoPendente.criado_em`, mas as descrições OpenAPI genéricas dizem `data_aposta` e UTC legado; a rota normaliza data sem offset para America/Sao_Paulo. Corrigir documentação/política gerada e definir o filtro de idade, sem prometer filtro que a API ignora.
- O resolver legado não recebe revisão esperada. Para decisões sobre evidência que pode mudar, publicar precondição opaca do servidor e a política de conflito/reconciliação; reutilizar #199 quando aplicável. Serialização no POST não prova que a evidência apresentada ao usuário ainda é a mesma.
- Separar resolução de Print não materializado, aposta existente, par legado e consolidação atual. Não enviar uma pendência sem aposta à rota que exige aposta materializada. Expor contexto de casa/instante e contas elegíveis pelo servidor; o site não decide atribuição temporal.
